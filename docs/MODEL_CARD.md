# SAFER model card

## Summary

SAFER is a college research prototype for three-class severity classification conditional on a hypothetical collision. It returns Slight, Serious, or Fatal scores and an optional validation-selected Fatal alert. It does not estimate collision occurrence, injury count, or an individual's real-world risk.

## Intended use

Use the app to demonstrate the synthetic generator, model comparison, calibration workflow, local/global explainability, and sensitivity analysis. Do not use it for road design decisions, emergency response, insurance, enforcement, driver assessment, or safety-critical decisions.

## Data

Datasets A (10,000 rows) and B (5,000 rows) are synthetic draws. Their categorical marginals are frozen from an earlier synthetic sample and their fields are sampled independently subject to declared date/speed derivations. Dataset C (2,000 rows) is sampled from B without replacement to create 1,503 Slight, 470 Serious, and 27 Fatal observations (1.35% Fatal). C overlaps B and is not an independent test. There are no measured crash speeds or live external data in this package.

The data include `collision_date`, 15 predictor fields, `simulator_noise`, `simulator_risk_score`, and `severity`. The predictor fields are day type, hour, posted limit, road type, junction detail/control, urban/rural context, weather, lighting, surface, vehicle type, driver age band, hypothetical simulated pre-impact speed, derived simulated speed excess, and derived simulated speeding indicator. `number_of_vehicles` has been removed because it is generally available only after impact. The model excludes the date, simulator noise, simulator risk score, and target label.

`actual_speed_kmh_simulated` is generated from the posted limit plus a declared random offset. It is hypothetical and should never be described as measured or estimated from an actual vehicle. The synthetic weight mapping and thresholds create the target; they are design assumptions, not empirically estimated physical relationships.

## Model

The artifact contains class-weighted Logistic Regression, Random Forest, and LightGBM base learners. Observation-specific entropy and disagreement weighting are selected on Dataset A validation Macro-F1. Probability calibration uses one-vs-rest isotonic/Platt candidates fit on a separate Dataset A calibration split. The final artifact selected beta=2, isotonic calibration, and a Fatal threshold of 0.40 using development data only.

## Evaluation

Dataset A is partitioned 60% fit / 10% calibrate / 10% validate / 20% untouched test. Dataset B is reserved for same-simulator evaluation. Dataset C is a low-Fatal-prior stress sample from B.

| Evaluation | Accuracy | Balanced accuracy | Macro-F1 | Fatal precision | Fatal recall |
|---|---:|---:|---:|---:|---:|
| Dataset A test | 84.75% | 84.91% | 84.98% | 85.68% | 85.87% |
| Dataset B same-simulator | 84.68% | 84.80% | 84.89% | 85.42% | 85.42% |
| Dataset C, 1.35% Fatal | 85.65% | 84.01% | 72.18% | 37.93% | 81.48% |

The high Dataset C accuracy should not be read without its lower Macro-F1 and Fatal precision. Dataset C contains only 27 Fatal examples. The adaptive beta=2 versus uniform-soft-voting differences on Dataset A are small; all paired bootstrap 95% intervals span zero for accuracy, balanced accuracy, Macro-F1, and Fatal recall. The model therefore does not show a clear adaptive-ensemble advantage in this experiment.

Calibration, permutation importance, and simulator-rule sensitivity results are in `outputs/`. Metrics represent recovery of generated labels only. No temporal/geographic real-data validation is supplied for the pre-crash feature schema.

## Explainability

The app provides local permutation SHAP contributions for a submitted scenario and global test-set permutation importance over five repeats. Both describe model behavior on synthetic inputs. Neither identifies causal effects.

## Limitations and risks

- The target is generated by the same transparent risk formula the model learns; synthetic test scores can overstate usefulness for real crashes.
- Independent field marginals may create unrealistic combinations and do not represent measured feature dependencies.
- Simulated vehicle speed and all speed-derived features are not observed data.
- Dataset B uses the same simulator; Dataset C is a subset of B.
- Calibration under one synthetic class prior may not transfer to another distribution.
- The validation-selected Fatal threshold changes the precision/recall balance and is not a clinical or operational alert threshold.
- The earlier STATS19 collision-level experiment included post-collision vehicle count and does not validate pre-crash prediction.

## Future validation needed

Use a legally permitted, representative crash dataset with fields known before impact; obtain measured or defensibly estimated speed if speed-based claims are desired; audit target and feature timing; validate on later years and a separate geography; report class-wise metrics and calibration under the deployment prior; and review false-positive and false-negative costs with relevant domain experts.
